# PSBA-XG: A Publish/subscribe Service-Based Architecture for Beyond 5G Systems (2024)

Sectiunea din plan: B . Tema: nedeclarat
## Problema (cum o formuleaza autorii)
In core-ul 5G, o actiune care cere informatii stocate in mai multe NF-uri produce lanturi lungi si secventiale de mesaje (exemplu: modificarea QoS implica SMF, PCF, gNB, UPF). SCP este descris ca nod centralizat, potential bottleneck si punct de esec. NWDAF are putine implementari din cauza dificultatii de a accesa datele altor NF-uri; UDM/UDR pot fi folosite doar de NF-uri specifice (Sec. I). Autorii urmaresc o abordare data-centric pentru reducerea mesajelor si latentei si pentru integrarea functiilor AI.
## Ce propun (metoda, pe scurt)
- Platforma PSBA-XG: componenta noua langa core-ul 5G, pe Service Based Interface, bazata pe publish/subscribe, care ingera datele de retea in unitati de stocare si Artificial Intelligence Functions (AIF), cu Northbound API pentru acces extern (Sec. III-A).
- Control-plane message mirroring: fiecare mesaj de semnalizare intre doua NF-uri este duplicat, unul spre NF-ul destinatie, celalalt spre platforma; platforma nu este parte obligatorie a retelei (Sec. III-C.1).
- Envoy proxy ca sidecar (un container per NF; nu pentru UPF si gNB), Apache Kafka ca broker, zece topicuri corespunzatoare NF-urilor din control plane, fiecare NF fiind publisher pentru topicul sau (Sec. III-C.2).
- Strat de administrare a deploy-ului cloud-native care ofera contextul necesar instantelor noi de NF, pe baza datelor ingerate (Sec. III-C.3).
- Un client Python (producer/consumer) traduce HTTP/2 in formatul Kafka si poate trimite cereri HTTP/2 sau PFCP spre core, actionand ca instanta SMF in cazul de utilizare (Sec. IV-A).
## Setup experimental (testbed real / emulare / simulare; unelte; scara; date)
- Open5GS (Release 17), dockerizat, pe Kubernetes (fiecare serviciu intr-un pod), UERANSIM pentru gNB/UE, Kafka via kafka-python-ng, Envoy; VM Ubuntu 20.04 cu 8192 MB RAM si 4 CPU i5-1145G7 @ 2.60 GHz (Sec. IV-A).
- Trei configuratii 5GC (Fig. 3): Vanilla (Open5GS cu SCP), Meshed (Envoy doar service mesh, SCP ocolit), PSBA (Envoy cu mesh si mirroring spre Kafka).
- Experiment 1: trafic SMF-NRF capturat cu Wireshark (mesaje heartbeat la 10 s, filtrate pe serviciul de inregistrare NRF), rulat circa o ora (Sec. IV-B).
- Experiment 2: modificare QoS declansata de un prag de 10 UE inregistrate; clientul trimite cerere HTTP/2 catre SMF; 14 rulari, mediate (Sec. IV-C).
## Experimente si metrici
- Timp de transmisie al mesajelor SMF->NRF in cele trei configuratii (ms), plus utilizare CPU/RAM.
- Timp de executie al procedurii de modificare QoS (trimiterea si confirmarea tuturor mesajelor din lant) in 5G standard vs. PSBA-XG; procedura bazata pe TS 23.502 (Fig. 5a/5b), cu fazele 1) cerere politica QoS la PCF, 2) aplicare la AMF si gNB, 3) inregistrare context nou; in PSBA-XG fazele 1 si 3 ruleaza in paralel cu faza 2.
## Rezultate raportate (cifre exacte, cu trimitere la tabel/figura)
- Fig. 4 (ms; Vanilla / Meshed / PSBA): mesaje heartbeat 77 / 78 / 80; medie 0.517 / 0.990 / 1.471; mediana 0.530 / 0.866 / 1.278; deviatie standard 0.217 / 0.335 / 0.462; minim 0.230 / 0.662 / 0.914; maxim 1.601 / 2.118 / 2.576.
- CPU circa 10% per CPU si 200-300 MB RAM per scenariu (Sec. IV-B.2).
- Fig. 6 (ms; 5G Standard / PSBA-XG): medie 30.719 / 9.836; mediana 26.665 / 6.789; deviatie standard 13.324 / 8.543; minim 18.030 / 5.356; maxim 73.343 / 38.103. Textul: mediana redusa de 4 ori, iar minim, maxim si medie de 3 ori; eliminarea mesajelor de tip fetch (ex. PCF-UDR) ar permite reducere de 5 ori (Sec. IV-C.2, V).
- Cresterea medianei per mesaj prin Envoy cu mirroring: 0.7 ms sau 140% (Sec. V).
## Limitari declarate de autori
Pragul de 10 UE este foarte mic pentru o retea reala; scopul este evaluarea arhitecturii, nu a capacitatii (Sec. IV-C.1). Envoy nu este desfasurat pentru UPF/gNB (protocoale diferite); lucrari viitoare: integrarea datelor UPF, proxy bazat pe eBPF, federated learning, core distribuit cu mai multe instante de NF, NF-uri stateless (Sec. III-C.1, V). NF-urile 5G nu sunt standardizate ca stateless (Sec. III-C.3). Mesajele de tip fetch raman trimise in experiment (Sec. IV-C.2).
