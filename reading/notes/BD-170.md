# From Automated to Autonomous: Hierarchical Agent-Native Network Architecture (HANA) (2026)
Cheie: BD-170 . DOI/link: 10.1109/lnet.2026.3693226 (arXiv:2605.20608) . Sursa textului: integral, arXiv v1 (20 mai 2026): https://arxiv.org/pdf/2605.20608
Sectiunea din plan: B . Tema: autonomous networks / agentic operations

## Problema (cum o formuleaza autorii)
Atingerea retelelor autonome de nivel 4/5 cere trecerea de la automatizare statica la inteligenta nativa pe agenti. Mecanismele existente (AIOps, SON, orchestrare SDN) sunt descrise drept controlere pasive si statice care gestioneaza evenimente nominale, dar nu au "agency" cognitiva pentru perturbari neprevazute; operatiunile actuale se bazeaza pe scripturi rigide (Sec. I).

## Ce propun (metoda, pe scurt)
- HANA: arhitectura de referinta ierarhica multi-agent, in trei straturi: Public Memory & Knowledge (metrici/evenimente, memorie publica accesibila prin MCP, cunostinte generale si de domeniu, "logic centralizata, fizic distribuita"), Cognitive Core (Orchestrator Agent dual-driven + Executive Agents, comunicare prin protocolul A2A) si Intelligent Toolbox (functii atomice, de ex. Access & Session Control, Policy & Charging; apelate prin MCP) (Sec. II-A, Fig. 1).
- Orchestrator cu doua mecanisme inspirate de teoria "slow/fast thinking": Internal Drive (module Self-awareness, Meta-goal, Choice Making cu predictii din situation awareness, Internal Goal transmis prin A2A) si External Drive (alerta -> Situation Awareness -> diagnostic preliminar -> Reactive State-Based Event catre un Executive Agent) (Sec. II-B).
- Executive Agents: Goal Management, Planning, Execution prin MCP, colectare de rezultate care actualizeaza Private Memory; conflictele dintre drive-uri se rezolva prin planificare pe prioritati, un eveniment External Drive cu incalcare de "hard constraint" intrerupe obiectivele interne (Sec. II-C).

## Setup experimental (testbed real / emulare / simulare; unelte; scara; date)
- Doua studii de caz in "un mediu 5G Core" (Sec. III). Caz A: scenariu de congestie "simulat" pentru o camera de supraveghere VIP cu cerinta de 2 Mbps. Caz B: trei scenarii de defect in core (AMF Node Unreachable; HTTP Connection Resources Insufficient pe un nod SMF; Total Session Capacity Level-1 Alarm).
- Implementarea core-ului 5G, LLM-ul folosit, numarul de UE/NF/noduri si sursa datelor: nedeclarate in text.

## Experimente si metrici
- Caz A (Internal Drive): comparatie intre terminal neprotejat, script bazat pe reguli si HANA; metrica: throughput (Mbps) in timp in perioada de congestie (Fig. 2). Agentul prezice un risc de incalcare a SLA, alege NGQI, ridica prioritatea fluxului si rezerva guaranteed bitrate (Sec. III-A).
- Caz B (External Drive): MTTR (minute) pe etape Dispatch/Analysis/Resolution, pentru "No Agent" (operare manuala), "Rule-Based" (arbore de decizie secvential: ping, stare pod, link) si "With Agent" (Tabel I). Exemplu detaliat: alarma "HTTP Connection Resource Exhaustion" pe SMF; agentul identifica maximul de conexiuni HTTP setat la 100 vs. 1000 recomandat din cazuri istorice, il actualizeaza la 1000 si face reload gratios (Sec. III-B).

## Rezultate raportate (cifre exacte, cu trimitere la tabel/figura)
- Fig. 2: terminalul neprotejat scade la aprox. 0.25 Mbps; scriptul bazat pe reguli introduce o latenta de aprox. 30 s (debouncing + executie secventiala) si intervine dupa incalcarea SLA; HANA este descris ca avand "zero-degradation" (rezervare inainte de congestie).
- Tabel I (MTTR total, minute; imbunatatire fata de No Agent): AMF Node Unreachable: No Agent 36, Rule-Based 17 (52.78%), With Agent 5 (86.11%); HTTP Connection Resources Insufficient: 14, 7 (50.00%), 3 (78.57%); Total Session Capacity Level-1 Alarm: 21, 16 (23.81%), 12 (42.86%). Timp de analiza AMF: 30 min manual, 15 min rule-based, 3 min cu agent. Rezolutia ramane 10 min pentru alarma de capacitate in toate trei variantele.
- Rezumatul/introducerea citeaza reducerea MTTR cu 86% (maximul din Tabel I).

## Steaguri factuale (da / nu / nedeclarat, cu sectiunea din lucrare)
- core 5G implementat (nu model)? nedeclarat - se spune "instantiate and validate within a 5G Core environment", fara detalii de implementare (Abstract, Sec. III).
- UE reale sau emulate? nedeclarat - congestia este "simulata" (Sec. III-A).
- digital twin al retelei? nu - nu este mentionat.
- prezice efectul unei actiuni inainte de a o aplica? nu - prezice incalcarea SLA (risc), nu efectul unei actiuni; Decision Making foloseste "predictive cost-benefit analysis" fara detalii (Sec. I, III-A).
- executa actiuni automat (bucla inchisa)? da - actiuni prin MCP/Intelligent Toolbox (modificare parametru HTTP, reload, rezervare GBR); "closed loop" in Fig. 1 (Sec. II, III).
- multi-site / geo-redundanta / failover de baza de date? nedeclarat - Public Memory descrisa ca "logically centralized but physically distributed" (Sec. II-A); nicio evaluare de failover de baza de date.
- evaluare prospectiva (predictie fixata inainte de experiment)? nedeclarat.
- rezultat masurat la nivel de utilizator (inregistrari, sesiuni)? nu - throughput al unui terminal (Fig. 2) si MTTR (Tabel I); fara metrici de inregistrari/sesiuni.
- observa traficul la SCP / proxy? nu - SCP nu este mentionat.
